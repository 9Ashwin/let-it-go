# start — 初始化工作区

把一个空仓库铺成**流程落得住**的工作区。铺的是**约定**，不是代码。

## 什么时候用 / 不用

**用**：新建或克隆下来的空仓库；已有仓库但没有任何约定（没有 `AGENTS.md`、没有需求目录约定）。

**已经有约定时不要重铺，改成体检**——重铺会覆盖掉人家写进去的红线。跑
`python3 <SKILL_DIR>/scripts/scan_workspace.py --audit`：它报的是**结构性空洞**（缺哪份文件、
缺哪个小节），照着补缺的那几处，其余一字不动。dolphin 那种铺满的工作区是 9/9。

## 产物：四份，只铺承重的

| 文件 | 回答什么 |
|---|---|
| `AGENTS.md` | **入口即路由**：底线（红线 + 裁决顺序）、任务路由、按目录路由、**开工清单**、收尾固定动作 |
| `CONSTRAINTS.md` | 工作区边界、路径与归属、资料归属、协作与回复 |
| `RULES.md` | 规则登记表：编号 / 规则 / 来源 / 优先级 / 适用条件 / 过期条件 / 状态 |
| `requirements/README.md` | 需求目录清单 + 资料约定（命名、产物位置、生命周期） |

**不要预造空目录**（`handbook/`、`templates/`、`decisions/`…）。空目录会让人以为那里有约定，
而真正的约定是长出来的——第一次需要写 SOP 时再建 `handbook/`。骨架在
[`references/templates.md`](references/templates.md)。

**为什么这几份文件是承重的：没写进仓库的约定，流程当作不存在。** 技能只读得到仓库里的东西——
`AGENTS.md` 没说的作用域根、门禁、冻结基线，对它就是不存在的，它会退回默认值。所以"我们一直是
这么做的"这种口头约定不算约定；要么写进这里，要么别指望它被遵守。反过来说，写进去的每一条都
要有事实支撑——**编出来的门禁命令比没有更糟，流程会拿它当证据**。

## 第 1 步：扫仓库，不要猜

```bash
python3 <SKILL_DIR>/scripts/scan_workspace.py --json
```

它给出：是否 git 仓库、默认分支、**门禁候选**（Makefile targets / package.json scripts /
`go.mod` / CI）、已有约定文件、测试文件、作用域根、**下一个需求序号**。

这几件事都能从文件系统读出来，所以**不要问用户**——问出来的答案还要他打字，读出来的不用。
扫不到门禁（比如纯文档仓库）才需要问。

## 第 2 步：只问人拍板的那一件

**红线只有人知道**——它们是这个仓库用代价换来的，任何扫描都读不出来。问一句，给候选让他勾：

> 这个仓库有哪几条**不可协商的底线**？（例如：永不 push 到默认分支 / 写业务数据需要明确授权 /
> 测试失败先归因再动测试）没有就写"暂无"——以后从复盘里长。

**其余一律不问**：作用域根、门禁、资料落点全用扫出来的事实 + 默认值，拿不准的标
`<待定>` 或 `[Assumption]`。问成一串清单会把这件事变成一次审批。

## 第 3 步：写四份

按 [`references/templates.md`](references/templates.md) 的骨架写。三条硬要求：

1. **只写有事实支撑的内容。** 扫不出来的留 `<待定>`，**不要编**——编出来的门禁命令比没有更糟，
   流程会拿它当证据。
2. **`RULES.md` 起步只放红线。** 其余从复盘里长：没有真实事件的猜测不写。这条规矩本身就是
   `RULES.md` 的价值所在——带来源的规则才可能在情况变了之后被正确废止。
3. **`AGENTS.md` 里不复述技能正文。** `/prd`、`/to-issues` 的产物形状属于技能；这里只说
   **作用域根、门禁、验收基线**这三件仓库才知道的事。

**覆盖已有的文件要先问。** 目标路径上已经有同名文件时，把"要覆盖哪个、会丢什么"说清楚再动手——
一份别人写的 `AGENTS.md` 里可能有你不知道的红线。

作用域根默认写 `requirements/<scope>/`。**不写也行**——流程会退到默认的 `tasks/<feature>/`
并自己找门禁（这条路有回归用例守着）。所以本技能买的是**确定**，不是**能跑**。

## 第 4 步：自检与报告

- 四份都在？作用域根在 `AGENTS.md` 与 `CONSTRAINTS.md` 里说的是同一个？
- 门禁命令**真跑过一遍**吗？跑不过就说明扫错了，改掉或标 `<待定>`。
- 没有预造空目录？
- **`--audit` 能全过吗？** 全过说明四份文件的骨架都在（dolphin 是 9/9，可以拿它当标尺）。
- 报告：写了哪四份、作用域根、门禁、红线几条、哪些标了 `<待定>`。

## 为什么 `AGENTS.md` 里要有「开工清单」

只有收尾动作是不够的：收尾管"别把没收尾的东西留下"，**开工管"别在坏地基上砌墙"**。
所以骨架里那条清单的第一件事是**先跑门禁看基线**，并且明写：**基线是红的就先修基线，
不要加新范围**——否则新工作会盖在一层已经红了的测试上，之后没人分得清是谁弄红的。

## 反模式

- **把模板整段抄进去**，包括与本仓库无关的条目——一份带别人约定的入口比没有更糟。
- **编造红线或门禁命令**：流程会拿它们当证据。
- **预造一堆空目录**。
- **把 `/prd` 的产物形状抄进 `AGENTS.md`**：那是技能的事，仓库只决定作用域根。
- **把这件事做成审批**：问一串问题、等一个"OK"。红线问一句，其余自己判。
- **闷头覆盖已有的约定文件**：那会丢掉别人写的红线。覆盖前先问。

## 与其它技能的关系

`star` 铺的 `AGENTS.md` 正是 `/prd`、`/to-issues`、`/loop-it` 开头那段「产物落点」读的
**仓库约定**：作用域根由它决定，门禁由它指定。铺完就可以直接说要做什么——规划半边会自己往下走。
