# 讲次映射与增量补充约定

本文件承担两件事：

1. **映射**：说明本 skill 的每个章节，其主张来自哪一讲次。讲次编号只是**溯源标签**，不是依赖——本仓库只做方法论提炼，读者没有原始素材也能完整使用本 skill。
2. **约定**：定义后续素材新增或修订时，增量如何一致地并进本 skill（见第二节）。

素材来源：一套关于 agent 驾驭工程的**内部方法论课程**。该素材实际含 24 个文件：开篇词、01–20 讲、直播回放、索引，以及单行占位文件。

## 二、【增量补充约定】

这套素材会继续更新。**未来素材迭代按本节流程补进本 skill**，以保证做法一致、可回查。

### 触发条件

命中任一条即启动本流程：

- 素材新增一讲；
- 素材修订某一讲（主张、结构或术语发生变化）；
- 直播、问答或补充材料提出了新的方法论主张。

### 步骤

1. **先读该讲全文**。不要只读摘要或标题；方法论常藏在"小结"之后的细节里。
2. **判定类型**：它属于"新诊断"（一种新的坏味道/病症）、"新处方"（一种新的施工法或重构手法），还是"改写既有主张"。
3. **落到对应文件**：
   - 诊断 → `references/diagnoses.md`，沿用固定五段（症状 / 成因 / 判据 / 处方 / 常见误判），并在处方处注明讲次。
   - 处方 → `references/playbook.md`，归入最接近的组；若确实不属于现有十一组，则新开一组并说明与现有组的边界。
   - 同时更新本文档第一部分的映射表（新增行或修订该讲所在行的主张描述）。
4. **同步更新 SKILL.md 的索引**：第 3 节体检清单（若新讲给出了新的可机检项）、第 4 节诊断索引、第 5 节施工索引。**索引必须可解析**——条目名与文件名要能被 `grep` 命中，路径要能点开；改动后自查一遍。
5. **在下方变更记录表追加一行**，格式：

   ```
   日期 | 素材讲次 | 动作（新增/修订/废弃） | 落到本 skill 的哪一节 | 一句话摘要
   ```

### 纪律

- **只增不改既有条目**：不重排既有段落，避免外部引用腐烂（别的文档按小节名/编号指向本 skill）。
- **推翻要留痕**：若某讲的新主张推翻了既有条目，把旧条目状态标为 `superseded` 并**保留**，在旁边注明被哪一讲取代、原因是什么；不要直接删除。依据是素材第 11 讲——删除要留痕，被清理的规则标记而不消失，审计时还能看到曾经有过它以及为什么被删。
- **编号是身份**：diagnoses 与 playbook 的条目编号一经使用不再重排、不复用；新增条目取当前最大编号加一。
- **每条主张必须有出处**：落进本 skill 的每一条都要写明讲次，不写无来源的"通用最佳实践"。
- **不在本 skill 内放入任何具体项目的隐私数据**（订单号、token、用户 ID、内部地址等）；示例一律抽象。
- **描述用"讲清 why"的方式**：不用全大写 MUST/ALWAYS；让读到的 agent 能读懂来龙去脉，能迁移，而不是死记。
