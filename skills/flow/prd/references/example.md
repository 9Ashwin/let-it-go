# 例子：怎么问、写出来长什么样

## 澄清：带字母选项

`ask_user_question` 一次把阻塞项问完，选项要能缩成一个短回答：

```
1. 这个功能的首要目标是什么？
   A. 改善新用户上手体验
   B. 提高用户留存
   C. 减轻支持负担
   D. 其它：[请说明]

2. 作用域到哪为止？
   A. 最小可用版本
   B. 完整功能实现
   C. 只做后端/API
   D. 只做 UI
```

人可以回「1A 2C」。**只有这两问是阻塞的**（目标决定 `acceptance` 怎么写，作用域决定边界）；配色、命名、目录结构这类不阻塞的，用合理默认值 + `[Assumption]` 直接往下。

## 一份填好的短 PRD

````markdown
# PRD: 任务优先级

## goal
用户能给任意任务设 high / medium / low，并让它跨会话持久化。
给每天开十几个任务的人用：现在列表只按创建时间排，重要的活会被埋掉，只能靠脑子记。

## acceptance
- [ ] 任务编辑弹窗里有优先级下拉框，当前值显示为选中态；选完刷新页面仍是所选值
- [ ] 每张任务卡片显示带颜色的优先级徽标（红=高、黄=中、灰=低），不悬停也能看到
- [ ] 过滤下拉框选 High 后列表只剩 High 任务；无匹配时显示空状态提示

## invariants
- 新任务默认 medium
- 既有任务的 priority 不回填成 NULL

## unknowns
- 优先级是否影响列内排序 —— [Assumption] 先不影响，保持现状排序
- 快捷键 —— 不做，需要时另开

## human_checkpoint
无
````

三件事值得注意：

- **没有用户故事 / 功能需求 / 成功指标章节**——这个功能里它们没有提供验收条件之外的任何信息。真有需要（多个用户角色、跨系统集成）就按需加，不是默认。
- **`acceptance` 三条能被同一次操作证明**：打开任务 → 改优先级 → 刷新 → 过滤。合并成一次观测，而不是拆成「第 1 页 10 条 / 最后一页不满 / 超范围返回末页」那种逐条列。
- **`unknowns` 里每条都有归宿**：要么 `[Assumption]`，要么明确「不做」。没有 `None`。
