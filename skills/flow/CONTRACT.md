# flow 契约

**这是 flow 的唯一真相源。** `prd` / `to-design` / `to-issues` / `loop-it` / `graph` / `review-it` /
`ship-it` / `merge-it` 八份 `SKILL.md` 只写三件事：**何时调用、边界、失败怎么办**。其余——工作状态长什么样、
证据怎么算、产物落在哪、一批活怎么不停——一律以本文件为准；技能里重复一遍就是下一次漂移的种子。

## 维护层级

改任何东西之前，先看它该写在哪一层：

| 层 | 写什么 | **不写什么** |
|---|---|---|
| `scripts/` + 自测 | 机器行为：排序、状态转换、证据门禁 | 判断 |
| `SKILL.md` | 何时调用、边界、失败怎么办 | 脚本已经实现的 schema、排序、状态机 |
| `references/` | 解释、例子、排障 | 状态机 |
| `README.md` | 入口路由：不看 SKILL 也能选对入口 | 细节规则 |
| `evals/` | 验证契约 | 反向定义流程 |

**同一条规则只能有一个实现。** 发现第二处，删掉它，改成链接。

**规则住在检查器的报错消息里，不住在散文里。** 检查器改写报错文本，把「为什么 + 怎么改 + 允许的例外」
直接写进消息——那是 agent 一定会读到的地方。SKILL.md 只写「跑哪条命令」；靠散文叮嘱（「记得跑门禁」
「记得更新工作状态」）在无人值守时必然失效。

## 0. 仓库约定：流程**读**，不**写**

流程读仓库根与各级目录的 `AGENTS.md`（有就用：门禁、作用域根、冻结基线）。**但不负责写它**——写仓库约定
是人的事。理由就是「技能只管什么时候用」那条：一个只在「初始化工作区」时才会被想起来的入口，在真正
需要它的那一刻（有人在改代码）不会被加载。仓库里没有 `AGENTS.md` 也不影响流程跑，它只是少了那几条
仓库特有的事实。

**通用底线不需要仓库声明**——它们是流程自己的默认，写在这里就是正本：

- **不 force-push**：它会重写别人已经基于其工作的历史。
- **不提交凭据**：密钥、token、`.env` 一律不进版本库。
- **默认分支只经 PR 进入**；没有远端时只本地 `--no-ff` 合入。
- **不把冻结的测试改弱来换绿**：改测试就是改契约。

**仓库特有的危险面由 `human_checkpoint` 兜底**——碰到公开 API / 数据迁移 / 权限 / 不可逆操作时停一次
问人（第 5 节）。所以「这个仓库不能碰什么」不需要提前写下来，它在碰到的那一刻被问到。

**门禁自己扫，不要猜**：Makefile targets（`check` / `test` / `lint` / `verify` / `ci`）、`package.json`
的 `scripts`、`go.mod`、`.github/workflows/`。扫不到就问人；**编出来的门禁命令比没有更糟**——流程会拿
它当证据。

## 1. 工作状态

一个对象，七个字段。**它是活的**：执行产生新事实就改它——不是先写一份长计划再开工，也不是写完就不动。

```yaml
goal:             这次要改变什么（一句话，可证伪）
acceptance:       验收条件；每条标它要哪一层证据（L1–L4）
invariants:       不能破坏什么
unknowns:         还不知道什么；自己定的决策标 [Assumption]
next_action:      下一步低风险动作
evidence:         已经拿到的观测：命令 + 结果 + 层级
human_checkpoint: 必须由人拍板的分叉（默认：无）
```

**七个字段分两处住，一处都不重复：**

| 字段 | 住哪 | 为什么在那 |
|---|---|---|
| `goal` `acceptance` `invariants` `unknowns` `human_checkpoint` | **契约**：GitHub issue 正文（没有远端时是 `issues/issue-NNN-<slug>.md`） | 变得少、要被人和不共享上下文的**全新子代理**读到、要能被协作者看见 |
| `next_action` `evidence`（+ `status`） | **进度**：作用域根的 `issues/.loop-state.json` | 每一步都在变，只有机器读，落盘要便宜 |

- 有 `origin` 且 `gh auth status` 通过 → 契约住 **GitHub issue 正文**。issue 正文就是契约：一个不共享
  这段对话的全新子代理拿起来就能照它行事。
- 没有远端，或 `gh` 没登录 → 契约住作用域里的 `issues/issue-NNN-<slug>.md`。**字段一模一样**，只是换了载体。

**`unknowns` 是一等公民，不许静默猜。** 模型会自己把空白补上，而误解会沿着多个文件往深处传播。
每条 unknown 只有两种归宿：**有人认领**，或者**显式写下「我按 X 假设推进」**（`[Assumption]`）。
`Open questions: None` 是最危险的一行——它通常是没想，不是没有。

**不是工作状态的东西：** PRD 长文、SPEC 长文、走查件、PR 描述、批末评论。那些都是它的**投影**——
只引用，不复制第二份真相。投影和它冲突时，**以它为准**；能只从状态 + issue 正文 + 代码重新推出来的
文档，删掉不损失信息。

**为什么要有这个对象：** 计划散在四处（PRD / issue 正文 / scope README / 检查点）时，同一个问题会有
三种口径，agent 遇到它就无法判断该信谁。执行产生新事实，新事实改计划；**计划不是执行的上游工厂。**
人读的形态只有一张短表（`loop_state.py summary`）——**不做第二份长文档，也不做「摘要的摘要」**；
如果需要再生成一份更短的版本才能读，那说明该写的不是文档，是状态。

## 2. 进度

`.loop-state.json` 记**走到哪了**——`status` / `next_action` / `evidence` / `branch` / `attempts`。
它和契约是两件事、两个计数器：

| | 契约（工作状态） | 检查点 |
|---|---|---|
| 回答 | 要做什么、什么算做完 | 走到哪了、下一步是谁 |
| 位置 | issue 正文 | 作用域根的 `issues/.loop-state.json` |
| 谁写 | 人确认 goal / invariants，agent 补 unknowns | **只有脚本**（`loop_state.py`） |

谁也不替代谁。**每个状态转换先落盘**——会话被 disarm、崩溃、或换一个会话接手之后，恢复靠它，
不靠聊天记录考古。子代理只回报，**落盘永远由编排者做**。

## 3. 三个 profile

| profile | 什么时候用它 | 路径 | **不做** |
|---|---|---|---|
| **单单元** | 一条 issue / 一张卡 / spec 里的一项，整个改动装得进一个上下文 | 读清楚 → 内联实现 → 门禁自证 → commit → `/review-it`（危险面时）→ `/ship-it`（开到 PR 就停） | **不碰检查点**、不建 worktree、不开 graph 波次、不写走查件、**不合入** |
| **串行批次** | 多条 issue 之间有真实阻塞边，要串行推进、崩溃可恢复 | 一条需求分支 + 每卡一个 commit + 每卡门禁；批末一次 `/review-it` + 一次 `/ship-it`（一个 PR） | 不做 per-issue PR（除非人点名）、**不合入** |
| **并行图** | 节点之间真并行（互不共享文件，能各自 worktree 隔离） | `/graph`：worktree 波 + fan-in | 波内不评审（评审留波末一次）、**不合入** |

**仪式量差一个数量级，这是硬契约。** 判据是**形态**，不是规模感：装得进一个上下文就是单单元。
单单元路径上出现 `.loop-state.json`、worktree 登记或 `workflow` 调用，就是错的——`evals/` 下的
单单元用例用机械断言守着这一条。

**「装得进一个上下文」不等于「定义好了」。** 手上只有一句诉求、落地方案还要自己定时，那不是单单元，
是还没成形的需求：先走规划半边（`/prd` → `/to-issues`），再回来。

**规划半边是交接，不是建议。** 做完 `/prd` 就**用 `skill` 工具加载 `/to-issues`**，拆完卡再加载
`/loop-it`（或 `/graph`）——同一个回合里走完，别把控制权收回自己手里，也别用「我判断它是单单元」
跳过交接：那个判断属于被加载的那个技能。实测踩过一次：`prd` 落盘后直接开写代码，整条链一步没走，
直到用户当面追问「为什么不建 issue 不开 loop」才回头。

**判据不是「有没有计划文档 / SPEC」**，而是三件事：**验收条件可证伪、回滚路径明确、要哪一层证据已知**。
文档可以没有，判据不能没有。

## 4. 证据

四层，**不自动升级、不能互相替代**：

| 层 | 证明什么 | 典型动作 |
|---|---|---|
| **L1** 单元 / 静态 | 逻辑与边界分支、可编译 | 单测、`vet`、构建、lint |
| **L2** 组件 / 集成 | 存储约束、幂等、组件协作 | DB 读回、迁移幂等 |
| **L3** 本地真实链路 | 配置、连通性、真实契约 | 起服务按验收条件打一遍（`make smoke`） |
| **L4** 真实外部系统 | 用户实际看到的外部往返 | 外部系统的往返读回 |

- **每条验收条件先标它要哪一层，再给那一层的证据。** 层级写在证据里（`evidence add --layer`），
  **不写进验收条件本身**——写成「验收标准：L3 通过」会破坏可判定性。
- 观测是**命令 + 结果**，不是「测试通过」。缺层如实记录，不用推断补齐。
- **证据必须由能操作真实运行物的那一层产生。** 评判者不读 diff、不看静态截图、不接受「看代码觉得对」——
  L3/L4 的证据就是**真的把跑起来的东西点一遍**（起服务、打接口、读回状态）。这是「零人工闸门」能成立的
  前提：无人值守下自我验收必然放水。
- **任一条验收条件没有它那一层的证据 = 整体不放行。** 不是「大部分满足」，也不是记一个 waiver。
- **门禁永远绿是可疑的，覆盖率不是证据。** 覆盖率只说明某一行被执行过，不说明它的影响被验证过；
  一个从不失败的传感器说明它不必要——`evals/` 的历史用来**删**规则，不是用来加规则。
- **完成 ≠ 成功。** 「跑了但 401」「交了个空 diff 却声称仓库已经满足」都不算完成。**验收与复现步骤必须
  跑在当前这份未改动的代码上**，结果里带机器可读的事实（命令、退出码、trace id、读回的值）。
  读不到就记 `unknown` 并**指名 blocker**，不许记成通过。
- **证据地板：只有真正发生过的动作算证据。** 搜了没打开、读了没读到、绿灯但没跑验收——都不算。
  判据落在**已经拿到的观测**上，不落在「我对这个方案有多大信心」上。
- `shipped` 的机器门禁**只有一个实现**：`scripts/loop_state.py`。**缺证据它拦**（一条都没有、也没写
  `--waive` 时拒绝这次转移）；**层级不够它告警**——一条都没标层、或最高只到 L1/L2，照样放行但会把话说明白。
  这是刻意的：层数够不够是判断，不是可核验的事实。
- **写测试不是默认动作。** 能观测就不写测试；同一条规则重复验证的边际收益很快归零。测得的规律：
  **测试行数 ≈ 验收条件数 × 29**——想少写测试，杠杆是**减少验收条件的条数**，不是把测试写短。
  真实链路那一层（L3/L4）写多少单测都补不上。

## 5. 零人工闸门

- **没有审批闸门。** `/prd`、`/to-issues`、`/loop-it` 都不等「回复 OK」：落盘即视为可用，反馈当修订。
  审批闸门把澄清从连续过程切成瀑布（`问 → 写文档 → 等人批准 → 才敢继续`），而真实的澄清是
  `理解 → 做 → 观察 → 追问 → 调整`。
- **评审不是等人。** 放行判据是**门禁绿 + 每条验收条件有它那一层的证据**；任一条不达标就整体不通过，
  并给出具体反馈。**生成者与评判者必须分离**——评判者拿同一套标准、独立上下文，**逐条**判：

  | 这段改动谁写的 | 谁来评 |
  |---|---|
  | 你自己（`/loop-it` 单单元、批末） | **必须**派一个不共享上下文的子代理（`subagent`，不是 `subagent_fork`） |
  | 节点子代理（`/graph` 的 fan-in） | 编排器可以内联读——**它不是作者**；但对抗性评审（任务是找「看起来完成了其实没有」）仍要派一个没参与实现的人 |

  理由：审自己刚写完的代码是最弱的评审——「被要求评价自己产出的东西时，agent 会自信地夸它，
  哪怕在人类看来明显平庸」。**要拿到结论才能继续时传 `run_in_background: false`**：后台子代理不让
  本回合保持忙碌，headless 里整个运行会停在回合边界。
- **人只在两个地方被叫。** 一是 `human_checkpoint`：判据是**危险面，不是阶段**——碰了下面任何一条
  就停一次等人，其余直接进 `理解 → 行动 → 检视 → 澄清 → 调整 → 再行动`：

  | 危险面 | 例子 |
  |---|---|
  | 公开 API / 兼容性 | 改签名、改响应形状、加必填字段 |
  | 数据迁移 / 破坏性变更 | 改 schema、回填、删列 |
  | 权限 / 认证边界 | 谁能做什么、token 生命周期 |
  | 不可逆 / 对外承诺 | 发布、删除、发版、对别人的承诺 |

  **停点要有真机制兜底**——冻结测试的哈希、证据层、只读沙箱、dry-run——**不能只靠 agent 自述
  「我先想过了」。** 把安全论证建立在「它答应先规划」上是错位的。
  二是**合入**。`/ship-it` 开到「PR 就绪」就停，合入归 `/merge-it`，而那一份**只有人能敲**
  （frontmatter 里 `disable-model-invocation: true`）。开 PR 可逆、也是给人看的；合入不可逆，在开源
  项目里本来就是维护者的动作。**这不是靠叮嘱，是靠模型碰不到那个技能。**
- **例外是有副作用的那一步**：真往**远端**建 issue、合 PR 之前，先把清单摆出来让人当场接住——
  建出去再撤要费手脚。写本地文件没有这个问题。
- **门禁落在工具与字段上，不落在提示里。** 「写在提示里的保证不是保证」：报告缺字段就**打回并指名
  缺哪一个**；行动声明必须由工具层写的日志背书（模型改不了那份日志），否则拒收——真实案例是
  「owner 已授权取消」写进了结论、却从没调用过取消，读起来完全正确。**零人工闸门 ≠ 零门禁。**

**问不到人不是失败。** 工具列表里没有 `ask_user_question`（无人值守部署）、调用被拒（你是子代理）、
或人已经说了「怎么落地你定」——三种情况都**自己定、写进工作状态、照常产出**。
**停在「等你回复」上是唯一一定错的做法**：DSH 里 `turn_end: completed` 就是这个回合的终点。

## 6. 不停

一批活开工之后不靠人推，靠 DSH 的 **goal**：

- **开工**：这一轮如果是人交来的活，先 `create_goal`。它的门禁是「**当前打开的回合里有人类消息** +
  **调用者是顶层 agent**」——**模型自己就能开，不需要人敲 `/goal`**；子代理开不了，所以只能在顶层开。
  `objective` 写这批活与验收，`max_goal_rounds` 按 issue 数自己给（**默认 256 太大**）。
- **收尾**：批末 `update_goal complete`。轮提示写的是「还有工作就保持 active」，不显式关掉会一直烧到上限。
- **中途被 disarm 不是灾难。** 单步输出触顶（`max-tokens`）、turn 被 abort、agent 报错、插件重载，
  都会让续跑驱动器停下（目标仍 active 但不再自动续跑）。**检查点还在**——人一句「继续」就
  `resume` 接着跑。所以每个状态转换都要先落盘。
- **无人值守 ≠ 不可打断。** 人任何消息入队都会推迟下一轮。这是设计，不是故障。
- **别用 `blocked` 逃班。** 自动轮里 `blocked` 要**连续三轮同一条件**才允许；难度大、不确定、
  还有活要干，都不算 blocked。
- plan mode 下不要建目标。

DSH 侧没有步数、工具调用数或时间上限（turn 循环是 `while (true)`，唯一的预算是轮数）。所以
**「不要停」的意思不是绕过什么限制，而是别把工作切成需要人推的碎片。**

**不要自己伪造续跑循环。** 一轮 turn 结束**不等于**目标完成——续跑由持有 goal 的那一方调度
（DSH 的 round driver），技能不写 `while (true)` 自己转圈，也不靠「记得下一轮再回来」。权威终态只认
goal 本身：批末 `complete`，真卡住了才 `blocked`。

## 7. 恢复

新会话接手只需要三件事：

1. `gh issue view <N>`（或本地 issue 文件）读**工作状态**；
2. `loop_state.py next` 拿**下一步**；
3. `git log --oneline -5` 看**最近发生了什么**。

**不读聊天记录。** 做不到这三步就说明有东西没落盘——那是流程的缺陷，不是接手人的问题。

## 8. 产物落点

**作用域内的形状固定，仓库只决定作用域根。**

- **作用域根**默认 `tasks/<feature>/`。仓库有约定（`AGENTS.md` 里的路由表，例如 `requirements/<scope>/`）
  就用它的根，**目录名不变**。仓库完全没约定时用默认值。
- 作用域内按需使用：`documents/`（PRD、SPEC、设计）、`issues/`（issue 卡片与检查点）、
  `notes/`（走查件、实现笔记、`environment.md`）、`records/`（复盘）、`checklists/`。
- 工作状态住在 GitHub issue 正文时，`documents/` 里的同名文件是它的**投影**。
- 一次性产物放 `tmp/<tool>/<时间戳>-<slug>/`，**不要落到仓库根或源码目录里**。
