# 摆清单与摘要报告：示例

## 把清单摆出来

拆得太碎和无意中切成横向切片是最常见的两种失败——摆出来，用户才能当场接住。

```
📋 已从 [PRD/SPEC] 生成 N 条 issue，按依赖顺序：

#1: 抽出 task-mutation 辅助函数（prefactoring）— Blocked by: none
#2: 用户能设置任务优先级并看到它持久化 — Blocked by: #1
    demo: 打开一个任务，选 High，刷新，仍是 High
#3: 用户能把任务列表过滤到某个优先级 — Blocked by: #2
    demo: 选 High，列表只剩 High 任务

过一遍这几条：
- 粒度：太细？"把 #3 和 #4 合并"。太粗？"拆开 #2"。
- 演示路径：哪条 issue 的 demo 是一层而不是一个行为，就是切错了——告诉我。
- 边：这些 "Blocked by" 链接是真的吗？有没有漏的或多余的？
- 未决项：哪条 Open question 没人认领？现在认领，或明确按什么假设推进。
- 有要改的当场说；没有就直接往下走。
```

## 摘要报告

```
✅ issue 创建完成！

来源：[PRD/SPEC 路径]
模式：[GitHub / 本地]（依据：[有 origin 且 gh 已登录 / 无远端]）
创建 issue 数：N（按依赖顺序）

#  | 标题（行为）                    | Blocked by | 标识
---|---------------------------------|------------|------------
1  | 抽出 task-mutation 辅助函数     | —          | #42 / 01-*.md
2  | 设置并持久化任务优先级          | #1         | #43 / 02-*.md
3  | 按优先级过滤任务列表            | #2         | #44 / 03-*.md

前沿（没有未决阻塞，现在就能开始）：#1
```

报告之后按形态直接往下——派发表见 [`../SKILL.md`](../SKILL.md)。两条要明说的注意事项：

- 长跑目标**不会自动关闭卡片**——做完自己更新它的状态。
- 只有前沿这些 issue **不**改同一批文件时，并行派发才安全；`/graph` 用每节点一个 worktree 加一道 fan-in 屏障强制这一点，作用域重叠就改串行。
