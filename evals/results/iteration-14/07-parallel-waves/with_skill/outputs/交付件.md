## 任务

这个仓库有三件事要做，它们之间有**真并行**：

1. `inventory.Reorder(items []Item) []Item` —— 返回数量低于 `ReorderAt = 5` 的条目，
   按数量升序排，数量相同按 SKU 升序。只碰 `inventory/`。
2. `pricing.BulkTotal(cents, qty, discountPct int) int` —— 金额减折扣，折扣向下取整
   （`cents*qty` 减去 `cents*qty*discountPct/100`）。只碰 `pricing/`。
3. `report.LowStockLines(items []inventory.Item, unitCents map[string]int, discountPct int) []string`
   —— 对每个待补货的条目输出一行 `"<sku> x<qty> = <金额>"`，顺序与 `Reorder` 一致，
   金额用 `BulkTotal` 算。它**依赖前两件**。

前两件互不依赖，第三件依赖前两件。

做完把三件集成到一起，`make check` 要绿。这个仓库没有 GitHub 远端，不要开 PR；
最终结果留在默认分支上（验收直接在这里看）。

## 风险点

- `report.LowStockLines` 只委托 `inventory.Reorder` 的排序与 `pricing.BulkTotal` 的金额，
  没有自己复制排序/折扣逻辑，所以两个依赖的语义就是它的语义。
- `unitCents` 缺 SKU 时用 Go map 零值 0 分计，这是规格未明说但唯一自然的选择；已在
  `TestLowStockLinesOrderAndAmounts` 里以 `D x2 = 0` 固化。
- `discountPct` 只按规格对非负金额设计（Go 整数除法）；未对负数折扣做防御，规格也未要求。
- `inventory/reorder_test.go` 里 `TestReorderDoesNotMutateInput` 的「返回切片不共享底层数组」
  断言比较的是结构体值，本身偏弱；不过入参不可变由前面的 `reflect.DeepEqual` 快照断言覆盖。

## 实现总结

**核心变更**
- `inventory`：导出 `ReorderAt = 5` 与 `Reorder(items []Item) []Item`（过滤 `Qty < ReorderAt`，按 `Qty` 升序、同 `Qty` 按 `SKU` 升序，先复制再排序）。
- `pricing`：新增 `BulkTotal(cents, qty, discountPct int) int`，在 `Total` 基础上减去向下取整的折扣。
- `report`：新增 `LowStockLines(items, unitCents, discountPct) []string`，逐条输出 `"<sku> x<qty> = <金额>"`。
- 新增 3 个测试文件，覆盖边界、排序、折扣取整与缺 SKU 情形。

**实现亮点（Highlights）**
- `report.LowStockLines` 不做任何重复逻辑：顺序委托 `inventory.Reorder`，金额委托 `pricing.BulkTotal`，格式化复用既有 `report.SKULine`，依赖边界最小。

**设计决策（Design Decisions）**
- 阈值以导出常量 `ReorderAt` 表达，避免魔法数字。
- `unitCents` 缺少 SKU 时按 0 分计——复用 Go map 零值，不额外分支。
- `Reorder` 返回新切片且不修改入参，避免调用方共享底层数组。

**偏离（Deviations）**
- None — 三处实现与用户给出的公式和输出格式一致。

**权衡（Tradeoffs）**
- 折扣用 Go 整数除法向下取整（符合规格 `cents*qty*discountPct/100`），不引入浮点，避免舍入误差。
- 波 0 先合入 `main` 再派发波 1：`report` 需要 `main` 上真实存在的 `inventory`/`pricing`，这比让 node-3 复用未集成分支更简单可靠。

**待确认（Open Questions）**
- 无。规格中 `discountPct` 假定为非负整数百分比。
