# 001 按仓库配置低库存阈值

## 需求

低库存阈值现在是所有仓库共用的全局值 `DefaultLowStockThreshold`。业务要能按仓库单独调整；
**没配的仓库继续走原来的默认值**。

配置放 `config/thresholds.json`（见 `config/README.md`）。改配置**不能要求重新构建**——
运维直接改文件就要生效。

## 验收条件

- [x] `config/thresholds.json` 是「仓库名 → 阈值」的 JSON 对象；文件为 `{}` 或不含某仓库时，
      该仓库的 `LowStockThreshold` 返回 `DefaultLowStockThreshold`。
- [x] 配置了的仓库，`LowStockThreshold` / `IsLowStock` / `LowStockWarehouses` 都用配置值，
      且保持严格小于（等于阈值不算低库存）。
- [x] 改文件后不需要重新构建或重启，下一次判定就读到新值。
- [x] 配置缺失或损坏时整体回退默认值，不影响判定。
- [x] 原有断言未被改弱，`make check` 绿。

## 落地

- `inventory/thresholds.go`：每次判定重新读配置；从当前目录逐级向上找 `config/thresholds.json`，
  所以从仓库根启动、或 `go test` 在 `inventory/` 下运行，读到的都是同一份文件。
- `inventory/stock.go`：阈值判定改为查配置，未命中回退默认值。
- `inventory/thresholds_test.go`：覆盖配置命中、回退、改文件即时生效。

## 决策记录

- **每次调用重读文件**，而不是启动时加载：这是「改文件即生效、无需重新构建」最直接的实现，
  也避免缓存带来的陈旧值。配置很小，代价可接受。
- **向上查找配置文件**：仓库没有 `main`，测试的工作目录是 `inventory/`；向上找能让固定位置
  `config/thresholds.json` 在仓库根和子目录下都可用。
- **JSON 用扁平映射**：`{"仓库名": 阈值}` 一眼能懂，不引入额外包装层。

## 落地方式

配置在 `config/thresholds.json`，内容是「仓库名 → 阈值」的扁平 JSON 对象：

```json
{
  "shanghai": 10,
  "xian": 3
}
```

- 配了的仓库用配置值；**没配的（含空文件/缺文件）回退 `DefaultLowStockThreshold`（5）**。
- 判定语义不变：严格小于。
- **改文件即时生效，不用重新构建或重启**——每次判定都重新读文件，不做启动时缓存。代价是每次判定读一次小文件，对配置这种场景我认为可接受，也避免缓存陈旧值。

## 关键实现

- `inventory/thresholds.go`（新增）：读配置 + 解析；配置路径默认 `config/thresholds.json`，从当前目录**逐级向上找**。这样从仓库根启动、或 `go test` 在 `inventory/` 下跑，读到的都是仓库根那份配置。
- `inventory/stock.go`：`LowStockThreshold` 改为查配置；`LowStockWarehouses` 每次调用只读一次配置，避免按仓库重复读文件。
- `inventory/thresholds_test.go`（新增）：覆盖配置命中、未配置回退、**改文件后无需重建即读到新值**、缺失/损坏回退、`LowStockWarehouses` 混合场景。
