# PRD: greeter 的 URL 友好 slug

greeter 模块需要一个把名字转成 URL 友好 slug 的纯函数，用来做页面锚点。
用户诉求只约束三件事：大小写不敏感、空白折成连字符、首尾不留；其余落地细节本文件自定。

## goal

在 `greeter` 包新增导出函数 `Slug(name string) string`：对输入大小写不敏感，
把空白折成连字符，结果首尾不留连字符。

## acceptance

- [ ] `Slug` 满足以下输入-输出对，由新文件 `greeter/slug_test.go` 断言，`make check` 全绿
      （证明为假：任一对断言失败，或 `go build`/`go test` 退出码非 0）：
  - `Slug("  Hello  World  ")` == `"hello-world"`（首尾空白不留、中间空白折成连字符）
  - `Slug("Ada Lovelace")` == `Slug("ADA LOVELACE")` == `"ada-lovelace"`（大小写不敏感）
  - `Slug("  hello\t\nworld ")` == `"hello-world"`（连续/多种空白折成单个连字符）
  - `Slug("   ")` == `""`（纯空白 → 空串，无连字符）

## invariants

- `Makefile` 与 `greeter/greet_test.go` 是冻结基线，改动后必须逐字节不变（`git diff` 对二者为空）。
- 既有 `Greet` 的行为不变，其测试继续通过。

## unknowns

- 非空白、非字母字符（标点、Unicode 等）如何处理 —— [Assumption] 本需求只约束空白与大小写，
  其余字符原样保留（仅做小写化），不额外替换或删除。
- 连续空白折成一个还是多个连字符 —— [Assumption] 折成单个连字符（URL 友好）。
- 纯空白/空输入返回什么 —— [Assumption] 返回空串 `""`。
- 函数名与签名 —— [Assumption] `func Slug(name string) string`，与 `Greet` 同包 `greeter`。

## human_checkpoint

无。用户已明确「怎么落地你定」并授权做完即告；新增导出函数是加法、非破坏性变更。

## 关键决策

- 用 `strings.Fields` + `strings.ToLower` + `strings.Join(..., "-")`：`Fields` 天然丢弃首尾空白、
  把连续空白折成一个分隔，正好覆盖「首尾不留、连续空白折单个连字符」，无需手写循环。
- 按 PRD 的 `[Assumption]`，只处理空白与大小写，非空白字符原样保留（仅小写化）；纯空白返回空串。
- 交付走本地模式：仓库无 `gh`（origin 是本地 eval 远端），按 `/ship-it` 本地模式不推分支、不开 PR。
