### `requirements/001-per-warehouse-low-stock-threshold/README.md`

# 001 按仓库配置低库存阈值

## 背景

低库存阈值原先是一个全局常量 `DefaultLowStockThreshold`，所有仓库共用。
业务需要按仓库单独调整，未配置的仓库仍走原来的默认值。

## 需求

- 每个仓库可以有自己的低库存阈值，统一配置在 `config/thresholds.json`。
- 配置里没有出现的仓库，阈值仍是 `DefaultLowStockThreshold`。
- 改配置不能要求重新构建：运维直接改文件就该生效。

## 配置格式

`config/thresholds.json` 是「仓库名 -> 阈值」的 JSON 对象：

```json
{
  "beijing": 10,
  "shanghai": 3
}
```

- 只写需要覆盖默认值的仓库，阈值为整数。
- 文件缺失或 JSON 非法时，所有仓库整体回退到默认值。

## 设计决定

- 每次调用 `LowStockThreshold` 都重新读文件，不做进程内缓存。这是“改文件即生效”
  最直接的实现，本 fixture 规模下读盘开销可忽略。
- 文件定位：先从工作目录逐级向上找 `config/thresholds.json`，找不到再退回本包
  源码所在的仓库位置（兼容测试进程工作目录不是仓库根目录的情况）。
- 未改动 `LowStockThreshold` / `IsLowStock` / `LowStockWarehouses` 的函数签名。

## 验收

- `make check` 全绿。
- `inventory/per_warehouse_threshold_test.go` 覆盖：按仓库生效、改文件即时生效、
  未配置仓库回退默认值、配置缺失或非法时回退默认值。
- `inventory/stock_test.go` 与 seed commit 保持逐字节一致。
