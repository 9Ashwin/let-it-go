# PRD: 按仓库配置低库存阈值

## 评审状态

无需评审 [Assumption：无人值守会话里没有人类可应答「这次需要评审吗」这个问题；
按技能默认「照走」处理。若后续指定评审人，改为 `待评审 @X` 并补评审记录。]

## 简介

低库存判定目前所有仓库共用一个全局常量 `DefaultLowStockThreshold = 5`。业务需要个别仓库
使用不同的阈值（例如上海仓备货深、阈值更高）。本功能允许把「仓库 → 阈值」写进仓库根下的
`config/thresholds.json`；**没有配置的仓库继续使用原来的默认值**。运维直接改这个文件即可
生效，不需要重新构建或重新部署二进制。

## 目标

- 按仓库名读取各自的低库存阈值，未配置的仓库回退到 `DefaultLowStockThreshold`
- 配置集中放在 `config/thresholds.json`（见 `config/README.md` 的约定）
- 运行时读取配置文件：改文件即时生效，无需重新构建
- 配置文件缺失或内容不合法时，不 panic、不阻断调用，按「没有配置」处理
- 既有门禁 `make check` 保持绿，既有断言与行为不被破坏

## 用户故事

**Acceptance Criteria:**

- [ ] 配置里没有的仓库，`LowStockThreshold(warehouse)` 仍返回 `DefaultLowStockThreshold`
- [ ] 配置在**每次调用时**从磁盘读取：进程启动后改写文件，下一次调用就能观察到新值，无需重启或重新构建
- [ ] 配置文件不存在时，所有仓库都回退默认值，函数不 panic
- [ ] 配置文件内容不是合法 JSON 或类型不对时，按「没有配置」处理，函数不 panic

## 功能需求

- FR-1: 系统必须在仓库根下读取 `config/thresholds.json` 作为按仓库的阈值配置
- FR-2: 系统必须把配置中某个仓库的值作为 `LowStockThreshold` 的结果返回
- FR-3: 系统必须对配置中不存在的仓库返回 `DefaultLowStockThreshold`
- FR-4: 系统必须在每次调用时重新读取配置文件，使改动无需重新构建即可生效

- FR-6: 系统必须保持 `LowStockThreshold(warehouse string) int`、`IsLowStock`、

- 不做配置热重载通知、不做文件变更监听（每次调用读盘已满足「即时生效」）

- 不引入环境变量或数据库作为配置来源
- 不给阈值加范围校验或业务规则（例如正数约束）——用户没要求
- 不改 `LowStockWarehouses` 的排序行为

# 按仓库加载低库存阈值（运行时读 config/thresholds.json）

## Goal
让每个仓库有自己的低库存阈值：从仓库根的 `config/thresholds.json` 读取「仓库名 → 阈值」，
配置里有的仓库用它的值，没有的（含配置缺失/损坏）回退 `DefaultLowStockThreshold`。
配置必须在**运行时**从磁盘读取，运维改文件即时生效，不需要重新构建。这是端到端的一条窄路径：
配置文件 → 读取 → `LowStockThreshold` → 既有 `IsLowStock` / `LowStockWarehouses`。

## Non-goals
- 不做文件监听或热重载通知（每次调用读盘即可满足即时生效）
- 不加环境变量 / 数据库配置源，不做阈值审计或历史
- 不加阈值范围校验（负数、0、超大值按原样使用）
- 不引入 `go:embed`（那会要求重新构建，违反约束）
- 不改 `LowStockThreshold` / `IsLowStock` / `LowStockWarehouses` 的签名与排序/严格小于语义

## Demo path
给 `config/thresholds.json` 写入 `{"shanghai": 20}`，直接（不重新构建）观察：
`LowStockThreshold("shanghai") == 20`，`LowStockThreshold("chengdu") == DefaultLowStockThreshold`；
删除该文件后，两者都回到默认值。

## Acceptance Criteria
- [ ] 仓库根下新增 `config/thresholds.json`（JSON 对象 `{"<仓库名>": <整数>}`）
- [ ] `LowStockThreshold("shanghai")` 在配置 `{"shanghai": 20}` 时返回 `20`
- [ ] 配置里没有的仓库返回 `DefaultLowStockThreshold`（值仍为 5）
- [ ] 在同一进程内改写配置文件后，下一次 `LowStockThreshold` 调用即返回新值（证明运行时读取、无需重新构建）
- [ ] `config/thresholds.json` 不存在时全部回退默认值，函数不 panic
- [ ] 配置文件不是合法 JSON / 类型不符时全部回退默认值，函数不 panic
- [ ] 新增测试覆盖上述配置生效、回退、缺失路径，且测试自行保存并恢复被改动的配置文件
- [ ] `make check`（build + test + vet）绿，且 `inventory/stock_test.go` 与 `Makefile` 未被改动
