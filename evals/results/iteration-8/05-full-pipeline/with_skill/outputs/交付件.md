# PRD: 低库存阈值按仓库可配

## 评审状态

## 简介

现在低库存阈值是一个全局常量（`DefaultLowStockThreshold = 5`），所有仓库共用。
实际业务里不同仓库的周转能力不同，需要各自设阈值；没有单独配置的仓库继续沿用原来的默认值。

本功能把阈值来源从写死的常量改成仓库根的配置文件 `config/thresholds.json`，
并且**在运行期读取**：运维改完文件即时生效，不需要重新构建，也不需要重启。

## 目标

- 每个仓库可以配置自己的低库存阈值。
- 没有配置的仓库回退到 `DefaultLowStockThreshold`（保持 5 不变）。
- 阈值从 `config/thresholds.json` 读取，改这个文件不需要重新构建即可生效。
- 不改现有对外函数签名与判定语义（`IsLowStock` 仍是严格小于）。

## 用户故事

### US-001: 按仓库读取阈值
**Description:** 作为业务方，我想要给单个仓库设低库存阈值，以便不同仓库用自己的口径判定低库存。

**Acceptance Criteria:**
- [ ] `LowStockThreshold(warehouse)` 在 `config/thresholds.json` 里配了该仓库时返回配置值
- [ ] 没有配置该仓库时返回 `DefaultLowStockThreshold`
- [ ] 配置文件缺失、读不出来、或内容不是 JSON 对象时，一律回退默认值，不 panic
- [ ] `IsLowStock` 保持严格小于：数量等于阈值不算低库存
- [ ] `make check` 绿

### US-002: 改配置即时生效的端到端测试
**Description:** 作为 QA 工程师，我想要一个覆盖「改配置文件 → 阈值生效」完整路径的自动化集成测试，
以便接住「配置被固化进二进制 / 进程内缓存旧值」这类回归。

**Acceptance Criteria:**
- [ ] 自动化测试在同一进程内完成：写 `config/thresholds.json` → 调用 `LowStockThreshold` → 断言读到新值
- [ ] 测试改写文件后无需重启/重新构建，下一次调用即返回新值
- [ ] 覆盖失败路径：删除配置文件后所有仓库回退默认值
- [ ] 测试自己还原现场（改动的真实配置在结束时恢复原样），可独立重复运行
- [ ] 通过 `go test ./...` 运行，`make check` 绿
- [ ] 配置没有被 `go:embed` 或其它构建期手段固化进二进制（源码里无 `go:embed`）

## 功能需求

- FR-1: 系统必须把 `config/thresholds.json` 解析成「仓库名 → 阈值」的映射。
- FR-2: `LowStockThreshold(warehouse)` 必须在映射里存在该仓库时返回其配置值。
- FR-3: `LowStockThreshold(warehouse)` 必须在映射里不存在该仓库时返回 `DefaultLowStockThreshold`。
- FR-4: 配置文件不存在、读取失败或 JSON 无法解析成对象时，系统必须回退到全部默认值。
- FR-5: 系统必须在每次判定时重新读取配置文件，使外部编辑无需重新构建即可生效。
- FR-6: 系统必须能从仓库根或仓库内的子目录（例如 `inventory/`）定位到仓库根的 `config/thresholds.json`。
- FR-7: `IsLowStock` 必须保持 `quantity < threshold` 的严格小于语义。

## 非目标

- 不把默认值 `DefaultLowStockThreshold` 做成可配置项（需求明确「没配的走原来的默认值」）。
- 不引入配置热重载的守护进程、文件监听或后台 goroutine。
- 不改 `LowStockWarehouses` 的排序语义与函数签名。
- 不做配置校验 CLI、不做多环境 profile、不做按商品维度细分。

## 设计考量

- 配置格式为扁平 JSON 对象，直观对应「仓库 → 阈值」，例如 `{"shanghai": 20}`。
- 不引入新依赖，只用标准库（`encoding/json`、`os`、`path/filepath`）。
- 新增逻辑放在 `inventory/thresholds.go`，`stock.go` 只改 `LowStockThreshold` 的取值来源。

# issue-001: 低库存阈值按仓库从 config/thresholds.json 读取

## Goal

让每个仓库在运行时从仓库根的 `config/thresholds.json` 取到自己的低库存阈值；没有配置的仓库回退
`DefaultLowStockThreshold`（5）。配置文件在每次判定时重新读取，运维改完文件即时生效，不需要重新构建、
不需要重启。阈值来源从写死的常量变成外部文件，且不改变现有函数签名与判定语义。

## Non-goals

- 不把默认值 `DefaultLowStockThreshold` 做成可配置项。
- 不引入文件监听、后台 goroutine 或任何热重载守护进程。
- 不改 `IsLowStock` 的严格小于语义，不改 `LowStockWarehouses` 的排序语义与函数签名。
- 不做配置校验 CLI、多环境 profile、按商品维度细分。
- 不替业务预设任何仓库的阈值（随仓库附空的 `{}` 配置）。

## Demo path

1. 写 `config/thresholds.json` 为 `{"shanghai": 20}`。
2. 调用 `LowStockThreshold("shanghai")` 返回 20；`LowStockThreshold("beijing")` 返回 5。
3. 同一个进程内把文件改成 `{"shanghai": 20, "beijing": 3}`，再次调用 `LowStockThreshold("beijing")` 返回 3
   ——没有重新构建、没有重启。
4. 删除 `config/thresholds.json`，`LowStockThreshold("shanghai")` 回到 5。

## Acceptance Criteria

- [ ] `config/thresholds.json` 里配了该仓库时，`LowStockThreshold(warehouse)` 返回配置值
- [ ] 文件里没配该仓库时，`LowStockThreshold(warehouse)` 返回 `DefaultLowStockThreshold`
- [ ] 配置文件不存在时，所有仓库返回 `DefaultLowStockThreshold`，不 panic
- [ ] 文件内容不是 JSON 对象（例如 `not json`、数字、数组）时回退默认值，不 panic
- [ ] 同一进程内改动文件后，下一次 `LowStockThreshold` 调用即读到新值（无进程内缓存旧内容）
- [ ] 源码里没有 `go:embed`，配置不被固化进二进制
- [ ] `go test ./inventory/`（cwd 是包目录）与从仓库根运行都能定位到同一份仓库根 `config/thresholds.json`
- [ ] `IsLowStock` 仍是严格小于：数量等于阈值不算低库存（原有断言保持绿）
- [ ] `make check` 绿

## Evidence required

- 每条验收条件对应 `inventory/thresholds_test.go` 中一条具名测试的输出（`go test -run ... -v ./inventory/`）：
  - `TestThresholdFromConfig` — 配置值生效
  - `TestThresholdFallsBackToDefault` — 未配置回退
  - `TestThresholdMissingConfig` — 文件缺失回退
  - `TestThresholdMalformedConfig` — 非法内容回退
  - `TestThresholdReloadsOnFileChange` — 同进程改文件后即时生效
  - `TestThresholdPathFromPackageDir` — 包目录 cwd 下仍定位到仓库根配置
- 基线上这些测试必须先红：改动前 `LowStockThreshold("shanghai")` 恒为 5，`TestThresholdFromConfig` 会失败。
- `make check` 的退出码与输出（`build` + `test` + `lint` 全绿）。
- 现有 `inventory/stock_test.go` 逐字节未改；`Makefile` 逐字节未改。
