### `requirements/001-per-warehouse-low-stock-thresholds/README.md`

# 001 — 按仓库配置低库存阈值

## 需求

低库存阈值目前是一个全局常量（`inventory.DefaultLowStockThreshold = 5`），所有仓库共用。
业务要能按仓库单独调整；**没配的仓库仍然走原来的默认值**。

配置必须放 `config/thresholds.json`（见 `config/README.md`），并且
**改配置不能要求重新构建**——运维直接改文件就生效。

## 决策

- **格式**：`config/thresholds.json` 是「仓库名 → 阈值」的扁平 JSON 对象，
  例如 `{"xian": 10}`。没列出的仓库回退到 `DefaultLowStockThreshold`。
  默认值留在代码里，配置只表达覆盖项。
- **热生效**：不用 `go:embed`（那会把配置烤进二进制，改配置就得重新构建）。
  改为运行期读取：`LowStockThreshold` 每次调用都重新 `ReadFile` + 解析，
  所以改完文件立即生效，无需重启或重构建。签名不变。
- **坏配置**：文件缺失、读不了或 JSON 非法时返回 nil，所有仓库回退默认值。
- **定位**：从当前工作目录向上查找 `config/thresholds.json`。
  `go test` 会把工作目录设成包目录 `inventory/`，向上查找才能命中仓库根的配置；
  从仓库根启动服务也是同一条路径。

## 落点

- `inventory/stock.go`：`LowStockThreshold` 改为读配置，新增 `thresholdFor` /
  `loadThresholds` / `findThresholdsConfig`；`LowStockWarehouses` 一次调用只读一次配置。
- `inventory/thresholds_test.go`：新增的行为测试（冻结的 `stock_test.go` 未改）。
- `config/thresholds.json`：新增，初始为 `{}`，不改变任何仓库的现有行为。

## 验收

- 配置里有的仓库用配置值，没有的回退 `DefaultLowStockThreshold`。
- 改完 `config/thresholds.json` 立刻生效（测试里同一进程连续两次读取验证）。
- 坏配置回退默认值，不 panic。
- `make check` 绿，且 `inventory/stock_test.go` 逐字节未改。

## 落地方式

**配置格式** `config/thresholds.json`（扁平「仓库名 → 阈值」映射）：

```json
{
  "xian": 10,
  "beijing": 3
}
```

没列出的仓库回退到代码里的 `DefaultLowStockThreshold`（仍是 5）——默认值留在代码里，配置只表达覆盖项。初始文件是 `{}`，即不改变任何仓库的现有行为。

**热生效**：没有用 `go:embed`（那会把配置烤进二进制，改配置就必须重构建）。改成运行期读取——`LowStockThreshold` 每次调用都重新读文件并解析，所以运维改完保存即生效，不用重启、不用重构建。函数签名不变，`IsLowStock` 不用动。

**定位**：从当前工作目录向上找 `config/thresholds.json`。这一步是必须的：`go test` 会把工作目录设成包目录 `inventory/`，写死相对路径会找错地方；向上查找让「仓库根启动服务」和「包目录跑测试」落到同一份配置。文件缺失/读不了/JSON 非法时全部回退默认值，不 panic。

顺带把 `LowStockWarehouses` 改成一次调用只读一次配置，避免同一次判定里阈值前后不一致、也避免每个仓库读一遍盘。
