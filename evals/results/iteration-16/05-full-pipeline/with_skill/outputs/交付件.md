## 简介

现在低库存阈值是 `inventory.DefaultLowStockThreshold = 5` 一个全局常量，所有仓库共用。
业务需要按仓库单独调阈值，例如成都仓阈值 3、武汉仓阈值 10。未在配置里出现的仓库，
仍然走原来的默认值 5。

配置统一放在本仓库的配置目录 `config/` 下，文件名 `config/thresholds.json`（用户指定）。
关键约束：**改配置不能要求重新构建**——运维直接改这个文件，下一次判定就要按新值生效，
不需要重新编译、重启或发版。

这是一个纯后端库（`package inventory`），没有 HTTP 入口，所以「生效」的可观测面就是
公开函数 `LowStockThreshold` / `IsLowStock` / `LowStockWarehouses` 的返回值。

## 目标

- 支持按仓库配置低库存阈值，配置来源固定为 `config/thresholds.json`。
- 未配置的仓库回退到 `DefaultLowStockThreshold`（5），行为与现状一致。
- 运维改完文件后，无需重新构建或重启即可生效（热加载）。
- 配置文件缺失、不可读或格式非法时，回退到默认值，判定不中断、不 panic。
- 不改变现有公开 API 的签名与「严格小于」语义。

## 设计决策（Design Decisions）

- 配置格式取顶层「仓库名 → 整数」映射，不套 wrapper；未配置即回退代码默认值，配置里不放默认值。
- 热加载用「每次判定重新 `os.ReadFile` + `json.Unmarshal`」，不做缓存与文件监听：无锁、无失效逻辑，天然并发安全。
- 路径放包内变量 `thresholdsFile`（默认 `config/thresholds.json`，相对进程工作目录），同包测试覆盖它指向临时文件。

## 偏离（Deviations）

- 评审发现 `{"仓库": null}` 会被 `map[string]int` 静默解成阈值 `0`，等于关掉该仓库的低库存检测。已改为 `map[string]*int`：`null` 按未配置回退默认值，非整数使整份配置作废；PRD 补 FR-8，issue 补一条 AC。
- 阈值取值：PRD 原写「非负整数」，实现不校验符号。按 PRD 的 `[Assumption]`（原样接受整数）把文档措辞对齐为「整数」，未加业务校验。

## 权衡（Tradeoffs）

- 每次判定读一次文件 vs 缓存 + mtime / 文件监听：选前者，牺牲少量 I/O 换实现简单与并发安全；配置文件很小。
- 坏配置整份回退 vs 逐键容错：选整份回退，语义简单、可预期；代价是一个坏值会作废同一文件里的好值。
