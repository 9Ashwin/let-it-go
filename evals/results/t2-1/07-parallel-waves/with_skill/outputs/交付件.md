## 任务

这个仓库有三件事要做，它们之间有**真并行**：

1. `inventory.Reorder(items []Item) []Item` —— 返回数量低于 `ReorderAt = 5` 的条目，
   按数量升序排，数量相同按 SKU 升序。只碰 `inventory/`。
2. `pricing.BulkTotal(cents, qty, discountPct int) int` —— 金额减折扣，折扣向下取整
   （`cents*qty` 减去 `cents*qty*discountPct/100`）。只碰 `pricing/`。
3. `report.LowStockLines(items []inventory.Item, unitCents map[string]int, discountPct int) []string`
   —— 对每个待补货的条目输出一行 `"<sku> x<qty> = <金额>"`，顺序与 `Reorder` 一致，
   金额用 `BulkTotal` 算。它**依赖前两件**。

前两件互不依赖，第三件依赖前两件。

做完把三件集成到一起，`make check` 要绿。这个仓库没有 GitHub 远端，不要开 PR；
最终结果留在默认分支上（验收直接在这里看）。

## 形态判定
三件事构成 `1→3`、`2→3` 的菱形：`inventory` 与 `pricing` 互不依赖（真并行），`report` 依赖两者。`loop-it` 管纯串行链，`graph` 管这种「有依赖但部分分支可并行」的 DAG，故加载 `graph` 并按其流程执行。

## 执行（两波）
- **规划**：作用域根 `requirements/001-low-stock/`，`nodes.json` 声明 3 节点；`graph_state.py plan` 分层为第 0 波 `{#1,#2}`、第 1 波 `{#3}`，写入 `.graph_state.json` + `graph.html` 看板。

- **第 1 波**：node-3 工作树基于已含依赖的 `main`，单节点派发；集成后 `make check` 绿，并入 `main`。
- **评审**：派一个**不共享上下文的对抗性评审子代理**，按 `review-it` 两轴评整份集成 diff——Spec 轴 0 缺失/0 多出/0 写错；Standards 轴八维度无阻塞发现，它独立复跑了 `make check`（exit 0）和 `go test -count=1`，并用 blob 哈希确认冻结测试未动。
