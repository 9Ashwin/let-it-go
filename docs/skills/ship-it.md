# ship-it

## What it does

把做完的、门禁绿、每条验收条件都拿到了它那一层证据的工作，交付到**「PR 就绪」**：提交、推分支、开 PR、补一条实现总结评论。

它到**「PR 就绪」**就停，合入不在这里。合入不可逆，在开源项目里本来就是维护者的动作，归 [`/merge-it`](../../skills/flow/merge-it/SKILL.md)，那一份只有人能敲；开 PR 可逆、也是给人看的，所以留在这一份。交付形态也不由技能决定，而由仓库决定：有 `origin` 且 `gh` 已登录走远端模式，否则走本地模式——只准备交付资料、不落默认分支，**不为走通 PR 流程去新建一个远端**。

工作状态、证据层、产物落点与放行判据见 [flow 契约](../../skills/flow/CONTRACT.md)；走查件的写法见 [走查件说明](../../skills/flow/ship-it/references/walkthrough.md)。

## When to reach for it

**调用方式**：frontmatter 没有 `disable-model-invocation`——你敲 `/ship-it`，或者模型在任务对得上时自己伸手。

**触发边界**：实现跑完、项目门禁是绿的，且每条验收条件都有它那一层的证据。单单元路径在 `/loop-it` 里内联收尾，串行批次在批末调一次，并行图在 fan-in 调一次；用户说「提交代码 / 创建 PR / ship-it」也算。

容易混的近邻：

| 你的处境 | 该用 |
|---|---|
| 改动做完，要开 PR / 提交 | **`/ship-it`** |
| 想合入已经开好的 PR | [`/merge-it`](../../skills/flow/merge-it/SKILL.md)——只有人能敲 |
| 还没评审、证据不齐 | 先 [`/review-it`](../../skills/flow/review-it/SKILL.md)；缺证据就回去补观测，不要先把 PR 开了再补 |
| 在 `/graph` 的节点里 | 节点止于 commit；评审与交付是编排器每波一次的事 |
| 仓库没有远端 / `gh` 没登录 | 还是这个技能，走本地模式——不是错误，也不用先修远端 |

## Common questions

**没有远端、或者 `gh` 没登录怎么办？**
本地模式，不是错误：不推分支、不开 PR，交付资料写进需求资料（检查点的 `note` 或卡片本身），四类内容与远端模式的评论一样。**不要因为技能写的是 PR 就去建一个远端**——判据是仓库里读得到的事实（有没有 `origin`、`gh auth status` 通不通），不是「流程上缺一步就补一个」。

**以前有个 `/walkthrough` 技能，哪去了？**
折进 `/ship-it` 了，成为交付前的 Step 0。折的理由是「总是一起用」：它一直紧挨着 `/ship-it` 被调用，合进来少一个 hand-off。范围不变——**每批或每波一份，绝不逐 issue 一份**，上限 30 行，一条命令 + 关键输出 + 截图路径；原始输出倾倒不是证据，是噪音。纯 L1/L2 的改动可以不写。

**一批多个 issue，为什么只有一个 PR？**
逐 issue 的走查证明的是一份可能活不过集成的 diff，而一批只有一个 PR。代价是 squash 之后逐项 commit 在默认分支上已经看不见，所以 PR body 必须带**逐项证据表**（commit / 关闭的 issue / 验收证据 / 人工验收），撤销单项就按表里的 commit 手工 revert；只写一行 `Closes #1 #2 #3` 等于既没法审计、也没法单独回滚。

**「人工验收」那栏没走过主路径，能先打勾吗？**
不能。如实写「尚未人工验收」——它是**标注，不是闸门**，放行只看门禁与证据。用户明确确认后才改，并写明确认依据。

**这条流程值这么多 token 吗？**
T1 实测：一个十几行的单单元改动，走技能要 133–184 秒 / 400–480 k token，不走技能 19–25 秒 / 50–76 k——差额几乎全是 `/review-it` 的子代理与 `/ship-it` 的交付流程。这是**设计**（生成者与评判者分离），不是缺陷；它也是这套流程必须配小任务才划算的原因。

## It's working if

- 运行停在 PR 就绪：你看到 PR 链接与合入命令被打印出来，**没有** merge、没有 `--admin`。
- 整批/整波只落在**一条**需求分支上，PR body 是逐项证据表，不是一个合成的 `Closes` 行。
- 走查件 ≤30 行、每批或每波一份，里面是命令与关键输出，不是几百行原始输出。
- commit message 概括改动、不带 issue 编号（编号由分支名与 PR body 的 `Closes #N` 承载）。
- 没有远端时，交付资料落在需求资料里，而不是多出一个新造的 remote。
