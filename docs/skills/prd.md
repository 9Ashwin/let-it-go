# prd

## What it does

把一句诉求变成**工作状态的契约五字段**：`goal` / `acceptance` / `invariants` / `unknowns` /
`human_checkpoint`——要做什么、什么算做完写在这一处，后面每一步都从它推导。

它和「先写一份完整 PRD 再等人批准」的默认做法分道扬镳：只问那些**不回答就写不出可验证
`acceptance`** 的问题，其余自己定并标 `[Assumption]`；落盘即视为可用，反馈当修订。所以它产出的
是一份短文档，不是一份要通读的模板——长度由未知量决定，九节结构不进默认路径。契约住在哪、证据
分几层、产物落在哪，见 [`CONTRACT.md`](../../skills/flow/CONTRACT.md)。

## When to reach for it

**调用方式：** 你敲 `/prd`，或者模型在任务对得上时自己伸手（没有 `disable-model-invocation`）。

该伸手的场合：

- 用户只给了一句诉求，落地方案还要自己定（「怎么落地你定」「文件格式你定」）。
- 需求还没成形：写不出可证伪的验收条件，或作用域边界还没划。
- 已经有人写好了验收条件（一条 issue 卡、spec 里的一项）→ 不需要 PRD，直接进 `/loop-it`。

与近邻的分界：

| 你其实想要 | 该用哪个 |
|---|---|
| 要什么、什么算做完（需求） | `/prd` |
| 为什么选这个方案、放弃了哪些备选 | [`/to-design`](../../skills/flow/to-design/SKILL.md) |
| 规格说明 / SPEC / 技术方案 | `/to-design`——这个词不归 `/prd` |
| 把已成形的需求拆成卡片 | [`/to-issues`](../../skills/flow/to-issues/SKILL.md) |

## Common questions

**它会停下来等我回 OK 吗？**
不会。落盘即视为可用，只有两种情况停：人明确说了「等评审过了再往下」，或「我只要文档」。要评审
就走 [`/review-it`](../../skills/flow/review-it/SKILL.md)，由它派一个不共享上下文的子代理——审自己
刚写完的东西是最弱的评审。审批闸门为什么被删掉，记在
[`.out-of-scope/no-approval-gate.md`](../../.out-of-scope/no-approval-gate.md)。

**我明明说了「怎么落地你定」，它怎么还来问？**
那正是它要避免的：决定权交出来之后，再拿落地细节回去问是把决定权还回去。问不到人的三种情况
（工具列表里没有 `ask_user_question`、调用被拒、人已经说了你定）一律自己定、标 `[Assumption]`、
照常产出。实测过一次反面：一条臂问了 4 个问题就结束回合，30 秒后整个运行到此为止，PRD 与 issue
卡一个都没产出。

**用户故事、成功指标、非目标这些章节去哪了？**
按需才有：有真实内容就写，没有就不写——它们通常不提供验收条件之外的任何信息。九节模板不进默认
路径是刻意的。

**验收条件写几条合适？**
杠杆是**条数**，不是每条写得多细。先问「这一条能不能和上一条用同一次观测证明」，能就合并。实测
的斜率是每条约 29 行测试，卡数减半并不会让每条变便宜；想少写测试就少写验收条件。

**界面好不好看，算验收条件吗？**
算，而且是一等验收条件，要附视觉验证。把外观划进非目标，等于允许交付一个能用但没法看的东西。

## It's working if

- 文档里没有 `Open questions: None`——每条 unknown 要么有人认领，要么带 `[Assumption]`。
- 澄清问题里没有一条是仓库里读得到的（有没有 `origin`、门禁是什么、产物该落哪）。
- 报告之后直接接上拆卡，中间没有「等你回复」的回合。
- 每条验收条件都能指出「哪次观测会让它为假」，而且几条能用一次操作串起来。
- 有界面的需求里，外观出现在 `acceptance` 里，而不是非目标里。
